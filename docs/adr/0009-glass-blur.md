# 毛玻璃：GPU 降采样 + 小图回读，不写 shader

ADR-0008 把玻璃定义为"半透明 + 高光 + 渐变"，因为 1.20.1 的 GUI 直接画不出背景模糊。用户随后明确要求 Windows 7 Aero 那种真实模糊，因此单独开这一份，只解决"模糊从哪来"。

## 决定

1. **模糊是屏幕空间的，不是逐面板的**：每 8 帧把主帧缓冲 `glBlitFramebuffer` 到一张 1/4–1/12 尺寸的 FBO（`GL_LINEAR` 降采样），再只回读这张小图（96–320px 宽），转成 `DynamicTexture`。
2. **不写 post shader**：复用固定管线与 `blit`，不引入 `shaders/post/*`、不接管主渲染管线。代价是回读有延迟、模糊是"降采样 + 双线性放大"而不是高斯；收益是与 Iris/OptiFine 的冲突面小、没有 shader 资产要维护。
3. **主题声明、全局开关、降级**：`effects.blur.enabled` / `strength`（0.1–1.0）；配置 `look.blur` 默认开；只有 `Surface.GLASS`（当前是千禧航空）真正消费；`motion` 的 45 FPS 降级同样关掉模糊。
4. **面板只做一次取样**：`ZtUi.panel` 在有模糊纹理时，先按面板屏幕坐标从大图里抠一块铺底，再叠 0x8C 透明度的主题色，最后才是高光/外框。面板外仍是不模糊的 3D。
5. **采样频率 8 帧**：模糊背景对枪的旋转不敏感，8 帧（约 7–8 次/秒）足够；回读放在渲染线程，`ByteBuffer`/`NativeImage` 复用，不每帧分配。

## Considered Options

- **Post shader / 原版 `blur.json`**：质量最好，但推翻 ADR-0008 的"不做 shader"，并且要处理主渲染管线、scissor、Iris 兼容；否决。
- **全分辨率 `glReadPixels` + CPU 高斯**：每帧 8MB 级回读 + CPU 卷积，1080p 下直接爆预算；否决。
- **打开界面时截一张静态图**：成本最低，但枪一旋转背景就对不上；否决。
- **继续用颗粒/噪声仿真**：已试过，观感不是 Win7 的"透过玻璃"，用户明确要真模糊；否决。

## Consequences

- 每 8 帧一次全屏 blit + 一次小图 `glReadPixels`；1080p 下回读约 100–200KB，远小于全屏。
- 模糊背景最多滞后 8 帧；在面板遮住 3D 下半屏的前提下不可感知。
- 与 shader 包共存时，读到的是 shader 处理后的最终画面，通常是想要的结果；但 shader 包若改写主帧缓冲格式，需实机验证。
- `FBO` 不完整或驱动拒绝时记一条日志并永久关闭本屏模糊，面板回落半透明底色，不崩。
- 玻璃主题的 `panel` 底色在有模糊时压到 0x8C；没有模糊时仍是原来的 D8，所以非玻璃主题与旧观感不受影响。
