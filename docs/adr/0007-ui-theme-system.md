# UI 主题系统：主题写在代码里、调色板是活动值、只改颜色与质感

界面要能在"预设按钮"旁边一键换外观，并带四套预设主题（默认（TACZ 青）/ MD3 质感 / 千禧航空 / Win 经典），其中默认主题还能改强调色。动手前盘出来的四条事实决定了这个功能怎么落：

- **配色一半是散的**：`ZtUi` 有 15 个命名常量，但 `ZtRefitScreen` 另有 39 行裸写色值（暗角、失效槽位、弹层底、toast、HUD 底衬…），`ZtUi.button()` 内部还有 10 行三态色。**不收拢这些，"换主题"必然漏一片**。
- **`ZtUi` 那 15 个是 `static final`**：编译期内联，运行时改值不会生效。
- **`roundedFill/roundedBorder` 的圆角写死 1px**，没有半径常量；`panel()` = 渐变 + 发丝边。想做"方角的 Win 经典"或"半透明的千禧航空"，圆角与底纹必须变成主题参数。
- **配置系统没有字符串型先例**，只有布尔 / 数值 / 枚举（`PROS_CONS_MODE` 是枚举先例），全项目运行时 `.get()`、不缓存进 `static final`。

决定：

1. **主题改到"颜色 + 质感"，不动布局、不做动效**：颜色全部可换；圆角、描边、面板底纹（纯色 / 渐变 / 半透明+高光）由主题给；**行高、面板宽、字号、内边距保持全局一套** —— 那些数字同时参与绘制、裁剪与命中检测，主题化等于每个主题一套点击判定。动效与背景模糊不做：1.20.1 的 GUI 没有背景模糊，"千禧航空"那种玻璃感按"半透明 + 高光 + 渐变"仿真。
2. **主题写在代码里**，一个 `ZtTheme` 记录体 + 若干常量实例，**不引入外部主题文件格式**（那是自造一套配置协议，与 ADR-0001 的口径相抵触，且没人真会拿它做主题包）。
3. **调色板是"活动值"，由单点刷新**：`ZtUi` 的调色板常量去掉 `final`，由 `applyTheme(ZtTheme)` 一处赋值；所有绘制点只认调色板，不再出现裸色值（第 1 条那份清单要全部收拢）。刷新点是：模组初始化、进改装界面、配置屏改动后。
4. **强调色用在哪，由主题自己声明**：默认主题的声明是"左侧竖条 + 选中行底色 + toast 强调条 + 滑块轨道"。**压在强调色上的文字与描边按强调色亮度自动切黑或白**，所以玩家输入 `#000000` 也不会出现"看不出那是个控件"。
5. **默认主题可调色（v1 只有一个全局自定义色）**：v1 只让"默认（TACZ 青）"暴露调色入口（其它主题的强调色是它调性的组成部分），配置里只有一个全局的 `accent_rgb`、仅默认主题使用；将来真要"每主题一份"再加项；另提供"恢复出厂色"。
6. **选择与自定义色存 Forge 客户端配置**（枚举 + `defineInRange` 整数），**不写进 `ztweaks/`**：这是"这台机器的外观偏好"，不该因为进了不同服务器就变样（ADR-0005 划的口径是 config 放功能开关与调参）。**两个入口读写同一项**：改装界面左上角的按钮，与配置屏新加的一行。
7. **覆盖自绘界面全部**：改装界面（含弹层、命名行、确认面板）、暗角、失效槽位配色、诊断 HUD 底衬、toast 都进主题；**配置屏保持 Forge 原生控件**，只让标题色跟随主题。
8. **四套主题"神似"而非"考据"**：关键色取近似值，一眼能认出风格即可，不抄字体与图标；主题名用风格描述而不是厂商名，中英各一份 lang key。
9. **入口交互**：按钮 = 色块 + 当前主题缩写，与"预设"按钮并排同尺寸；弹层点一次**不关**（方便连着比），点外部或 `Esc` 关，当前主题打勾；"调色"是弹层里的一行，展开成输入框（复用预设命名那套 `EditBox`），**边输边预览、回车落定、非法输入保持上一次有效值**。

## Considered Options

- **外部主题文件（json / 资源包）**：可以做"主题包"，但等于自造协议，且与 ADR-0001 的口径冲突。
- **只换颜色**：实现最省，但四个主题里三个会长成同一套皮肤的换色版，需求本身就落空。
- **连布局一起主题化**：能更像，但每个主题都要重算命中检测，收益远小于风险。
- **主题选择存 `ztweaks/`**：会跟着服务器变，玩家进不同服看到不同外观，属于"莫名奇妙的不一致"。
- **所有主题都开放调色**：自由度最高，但随手一改就破坏主题本身的调性，且"预设主题"的意义被稀释。

## Consequences

- 主题化的**前提是一次去硬编码的收拢**（约 55 处），这一步单独做、单独可验证，之后每加一个主题只是加一条数据。
- `ZtUi` 从"编译期常量"变成"运行时活动值"，与全项目"配置运行时 `.get()`"的做法一致；代价是调色板变成可变静态状态，**只允许 `applyTheme` 一处写入**。
- 新增主题 = 在主题表里加一条记录 + 两份 lang key，不需要动绘制代码。
- 将来若要放开"外部主题文件"，只需换掉主题表的数据来源，第 3–9 条都不受影响。
