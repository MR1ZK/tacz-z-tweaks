# 玩家本地状态存哪：游戏目录根、按用途分文件、按服务器隔离

配件**收藏**、改装**预设**、界面位置这三样要落盘，得先定写在哪。三条来自其他事实的约束（与 ADR-0001 的"不引入自定义数据"无关，那个禁的是替他人定义内容）：

- **不能进 `config/`**：整合包会打包 `config/` 并在更新时覆盖它，玩家攒的收藏与预设会被一次整合包更新冲掉。这类"东西自己没了"最难查。
- **也不能只靠存档目录**：客户端在多人服务器上没有本地存档可挂靠，收藏会凭空消失。
- 已有的 `config/z_tweaks-client.toml` 是 **Forge ModConfig**（功能开关与调参），与玩家状态是两回事，不合并。

决定：

1. **状态根在游戏目录根**：`<游戏目录>/ztweaks/`，与 TACZ 自己的 `<游戏目录>/tacz/` 同级（先例见 `GunPackLoader` 的 `FMLPaths.GAMEDIR.resolve("tacz")`）。
2. **按用途分文件，不合并成一个大 json**：`favorites.json`（高频小改）、`presets/<namespace>/<path>/<名>.json`（低频大对象，且玩家要能单独分享与删除）、`ui-state.json`（噪声级）。预设那条路径就是枪 id 直接落成目录层级：`:` 在 Windows 文件名里非法、`/` 本来就要分层，写不出 `presets/<枪id>/`；预设名做文件名安全化（非法字符替换、空名兜底），**显示名以 json 字段为准**，文件名只负责"能存能列"。
3. **多人按主机名隔离**：状态根切到 `<游戏目录>/ztweaks/servers/<host>/`，内部结构与单人完全一致。用**主机名**而不是 `host:port` —— 服务端换个端口不该让收藏丢失。
4. **写盘策略**：改动只标脏，关屏或延迟一两秒合批落盘；失败只记日志（丢的是玩家标记，不致命），但首次创建目录失败提示一次。

## Considered Options

- **`config/ztweaks/`**：合 Forge 惯例，但会被整合包更新覆盖。
- **存档目录 `saves/<世界>/ztweaks/`**：单人可用，多人没有落点；且按世界隔离会让玩家在每个存档里重复收藏同一批配件。
- **塞进 Forge ModConfig 的 toml**：Config 是给玩家调感的，不是给程序写的；混在一起会让"重置配置"顺手清掉收藏。
- **一个 `state.json` 装全部**：三者的写入频率与损坏半径不同，一次写坏全丢。

## Consequences

- 玩家的收藏与预设跨存档、跨整合包保留，换整合包不需要迁移代码。
- 整合包无法随包分发"出厂收藏/预设" —— 这本来也不该做，那是玩家状态。
- 同一台服务器上状态一致，换服务器则是另一份。这是刻意的：不同服的枪包不同，预设的可用性也不同。
- 状态文件不在 `config/`，所以"删掉 config 重置模组"不会误删收藏。反过来说，**重置收藏缺少现成的入口**，需要一个显式动作。
